Driver Node

👮‍♂️ 调度总指挥部 (Logistics Dispatcher / Driver Node)

spark.driver.memory / spark.driver.cores

调度总指挥部是 Spark 作业的大脑（Driver）。它不直接参与具体搬运，而是将用户提交的程序解析为 DAG 路线图、切割为 Stages，并将上万个分拣 Task 打包发给远程卡车。如果执行 `collect()` 会将所有货物拉回指挥部，极易爆仓崩溃。

核心配置建议 spark.driver.memory = 4g~32g
物流风险点 collect() 大数据导致指挥部 OOM 瘫痪
费曼直觉总结 指挥官手里的路线图要清淅，绝不能把全部包裹全拉回指挥室。

费曼四步法：把 Spark 物理模型讲给 10 岁孩子听

STEP 1 📦

数据量 = 待处理包裹吨数

1TB 原始日志相当于 1000 吨货物。经过 Parquet 压缩后体积极致缩小，但在解压分拣时又会膨胀。

STEP 2 ⏰

SLA = 早上 8 点送达死线

业务必须在 2 小时内出结果。如果死线极紧，就必须派入更多车队（Executors）并行干活。

STEP 3 🚚

Executor = 标准卡车车队

每辆卡车配 5 个搬运工（Cores），车厢大小（Memory）决定能装多少数据，防止中途爆仓（OOM）。

STEP 4 🔄

Shuffle = 跨园区调拨

当遇到 GroupBy / Join 时，所有卡车需要在高速公路上交叉拉货，这是最烧油（耗网络和磁盘）的环节。

Spark 架构与物流转运中心对照辞典 (Mapping Dictionary)

Spark Driver 物流调度总指挥

负责全局路线规划 (DAG Parsing)、包裹任务拆解与派发给各个卡车。

Executor Container 标准分拣卡车

真正干活的计算容器，包含一定数量的搬运工 (Cores) 和指定容积的车厢 (Memory)。

Partition / Block 标准打包件 / 切片

数据被切分为如 128MB 的标准箱子，每个搬运工一次处理一个箱子。

Shuffle Write / Read 跨园区货物调拨

按新 Key（如按目的地）把包裹重新分配给不同卡车，产生大量网络与磁盘 IO。
